# Kubernetes helpers

Modules that call the Kubernetes API or encode Pier conventions. The route handlers in [../routes/](../routes/README.md) take these as injectable dependencies, so tests don't need a cluster.

| File | Exports | Notes |
|------|---------|-------|
| `clients.ts` | `createK8sClients()`, `K8sClients`, `K8sClientsResult` | Loads kubeconfig once at startup, builds all four API clients (`CoreV1Api`, `VersionApi`, `AppsV1Api`, `NetworkingV1Api`), and returns them as a bundle. Never throws; errors are wrapped in `{ ok: false, error }`. Routes pass the result to handlers so the kubeconfig is loaded once per app, not per request. |
| `client.ts` | `isInCluster()`, `loadKubeConfig()`, `KubeConfigMode`, `KubeConfigLoader`, `LoadedKubeConfig` | Loads and validates kubeconfig: `in-cluster` if `KUBERNETES_SERVICE_HOST` is set and the ServiceAccount token exists, else `loadFromFile(KUBECONFIG)` if a path is given, else `loadFromDefault()` (`~/.kube/config`). Throws if there is no current context, or if `getCurrentCluster()` finds no cluster for it (`kubeconfig: context "<name>" has no cluster`). |
| `cluster-health.ts` | `getClusterHealth()`, `ClusterHealth` | Takes `CoreV1Api`, `VersionApi`, and `mode`. Calls `VersionApi.getCode()` plus `listNode()`. `ok` is true when there is at least one node and every node is `Ready`. Errors are thrown for routes to handle. |
| `list-pods.ts` | `listClusterPods()`, `podToSummary()`, `readyColumn()`, `PodSummary`, `ClusterPodsResult` | Takes `CoreV1Api` and `mode`. Calls `listPodForAllNamespaces()`, maps each pod to `{ name, namespace, phase, nodeName?, ready: "x/y", startedAt? }`. |
| `labels.ts` | `APP_LABEL`, `MANAGED_BY_LABEL`, `MANAGED_BY_VALUE`, `appSelector()`, `appLabels()` | `pier.app=<name>` identifies an app; `app.kubernetes.io/managed-by=pier` marks Pier-owned objects. |
| `apps.ts` | `listApps()`, `deploymentToApp()`, `deriveStatus()`, `App`, `AppStatus` | Takes `AppsV1Api` and namespace. Lists Deployments with label `pier.app`, sorted by name; excludes any with `deletionTimestamp` set. `name` comes from the label (falling back to `metadata.name`) and `image` from the first container. Status rules are in [../routes/README.md](../routes/README.md#get-apps). |
| `api-errors.ts` | `apiStatusCode()` | Extracts HTTP status code from Kubernetes API errors. Handles both `statusCode` (client-node ApiException) and `code` (legacy) properties. Returns `undefined` if not found or not an error. Used throughout to centralize status code checks. |
| `manifests/index.ts` | `buildDeployment()`, `buildService()`, `buildIngress()`, `CreateAppInput` | Pure builders: no API calls, no side effects. Construct typed Kubernetes manifests for apps with security defaults (Pod Security baseline, seccomp, no privilege escalation, `automountServiceAccountToken: false`), resource quotas (cpu, memory, ephemeral-storage), and readiness probes. Ingress requires `host` to be set. All objects are labelled with `pier.app=<name>` and `app.kubernetes.io/managed-by=pier`. Service and Ingress include owner references (blockOwnerDeletion: false) pointing to the Deployment for garbage collection. **Note:** Generated Ingress rules are HTTP-only; TLS is assumed to be handled by Traefik configuration. |
| `manifests/constants.ts` | `CPU_REQUEST`, `CPU_LIMIT`, `MEMORY_REQUEST`, `MEMORY_LIMIT`, `EPHEMERAL_STORAGE_REQUEST`, `EPHEMERAL_STORAGE_LIMIT`, `PROGRESS_DEADLINE_SECONDS` | Resource and scheduling constants extracted to keep manifests/index.ts under 250 lines. |
| `create-app.ts` | `createApp()`, `createAppSeralized()`, `AppExistsError`, `HostInUseError` | Orchestrates creation: pre-checks (deployment must not exist, host must not be in use in namespace), creates Deployment → Service → Ingress in order, rolls back on failure. `createApp` accepts optional logger to log rollback failures. `createAppSeralized()` serializes calls via a module-level promise chain (`createMutex`), making the host check and create atomic from concurrent requests (correct only with one backend replica; see [../routes/README.md](../routes/README.md#app-creation-race-condition-and-the-create-mutex)). Host check is now scoped to Pier-managed resources in PIER_NAMESPACE only. |
| `app-actions.ts` | `getLiveDeployment()`, `scaleApp()`, `restartApp()`, `deleteApp()` | Pure action functions for app lifecycle management, all 404-tolerant: <br/>`getLiveDeployment()`: returns Deployment or undefined on 404 or if `deletionTimestamp` is set (treated as gone). <br/>`scaleApp()`: uses `replaceNamespacedDeploymentScale` to set replicas (0–10). <br/>`restartApp()`: uses JSON Patch to update `kubectl.kubernetes.io/restartedAt` annotation, handling both "annotations exist" and "no annotations" cases. <br/>`deleteApp()`: deletes Ingress, Service, Deployment (with `propagationPolicy: Foreground`) in order, each 404-tolerant. |
