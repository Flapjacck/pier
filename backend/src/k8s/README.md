# Kubernetes helpers

Modules that call the Kubernetes API or encode Pier conventions. The route handlers in [../routes/](../routes/README.md) take these as injectable dependencies, so tests don't need a cluster.

| File | Exports | Notes |
|------|---------|-------|
| `clients.ts` | `createK8sClients()`, `K8sClients`, `K8sClientsResult` | Loads kubeconfig once at startup, builds all four API clients (`CoreV1Api`, `VersionApi`, `AppsV1Api`, `NetworkingV1Api`), and returns them as a bundle. Never throws; errors are wrapped in `{ ok: false, error }`. Routes pass the result to handlers so the kubeconfig is loaded once per app, not per request. |
| `client.ts` | `isInCluster()`, `loadKubeConfig()`, `KubeConfigMode`, `KubeConfigLoader`, `LoadedKubeConfig` | Loads and validates kubeconfig: `in-cluster` if `KUBERNETES_SERVICE_HOST` is set and the ServiceAccount token exists, else `loadFromFile(KUBECONFIG)` if a path is given, else `loadFromDefault()` (`~/.kube/config`). Throws if there is no current context, or if `getCurrentCluster()` finds no cluster for it (`kubeconfig: context "<name>" has no cluster`). |
| `cluster-health.ts` | `getClusterHealth()`, `ClusterHealth` | Takes `CoreV1Api`, `VersionApi`, and `mode`. Calls `VersionApi.getCode()` plus `listNode()`. `ok` is true when there is at least one node and every node is `Ready`. Errors are thrown for routes to handle. |
| `list-pods.ts` | `listClusterPods()`, `podToSummary()`, `readyColumn()`, `PodSummary`, `ClusterPodsResult` | Takes `CoreV1Api` and `mode`. Calls `listPodForAllNamespaces()`, maps each pod to `{ name, namespace, phase, nodeName?, ready: "x/y", startedAt? }`. |
| `app-pods.ts` | `getAppPods()`, `AppPod` | Takes `CoreV1Api` and namespace. Lists pods for an app using app label selector, returns `{ name, phase, ready, readyContainers, restarts, node?, startedAt?, waitingReason?, lastTerminationReason? }`. |
| `labels.ts` | `APP_LABEL`, `MANAGED_BY_LABEL`, `MANAGED_BY_VALUE`, `appSelector()`, `appLabels()` | `pier.app=<name>` identifies an app; `app.kubernetes.io/managed-by=pier` marks Pier-owned objects. |
| `names.ts` | `APP_NAME_PATTERN`, `APP_NAME_SCHEMA_PATTERN`, `POD_NAME_PATTERN`, `POD_NAME_SCHEMA_PATTERN`, `isValidAppName()`, `isValidPodName()` | DNS-1035 app names and DNS-1123 pod names; shared by route validation and JSON Schema patterns. |
| `app-lookup.ts` | `getLiveApp()`, `getAppRoute()`, `getApp()` | Helpers for reading live app state (#40). `getLiveApp()`: read Deployment, return undefined if 404/terminating/unlabeled. `getAppRoute()`: read Ingress, return `{ host, tls }` from the first rule (tls when `spec.tls` covers that host) or undefined. `getApp()`: combine both reads and return complete App with port/host/url. Rethrow non-404 errors for routes. |
| `apps.ts` | `listApps()`, `deploymentToApp()`, `deploymentPort()`, `ingressHost()`, `appUrl()`, `deriveStatus()`, `App`, `AppStatus` | Takes `{ apps: AppsV1Api; networking: NetworkingV1Api }` and namespace. Lists Deployments with label `pier.app` sorted by name; excludes any with `deletionTimestamp` set. Makes one parallel `listNamespacedIngress` call to populate hosts. `deploymentToApp()` now accepts optional `host` and includes port/host/url when available. `deploymentPort()` extracts port from containers[0] (prefer port named 'http'). `ingressHost()` extracts first rule's host, lowercased. `ingressHasTls()` is true when a `spec.tls` entry covers the first rule's host (case-insensitive). `appUrl(host, tls)` builds `https://` or `http://` URLs from that. Status rules are in [../routes/README.md](../routes/README.md#get-apps). |
| `api-errors.ts` | `apiStatusCode()`, `apiErrorMessage()` | Extracts HTTP status codes (`statusCode`, `code`, or JSON `body.code`) and safe error messages from Kubernetes API errors. |
| `manifests/index.ts` | `buildDeployment()`, `buildService()`, `CreateAppInput` (re-exports `buildIngress()`) | Pure builders: no API calls, no side effects. Construct typed Kubernetes manifests for apps with security defaults (Pod Security baseline, seccomp, no privilege escalation, `automountServiceAccountToken: false`), resource quotas (cpu, memory, ephemeral-storage), and readiness probes. Ingress requires `host` to be set. All objects are labelled with `pier.app=<name>` and `app.kubernetes.io/managed-by=pier`. Service and Ingress include owner references (blockOwnerDeletion: false) pointing to the Deployment for garbage collection. |
| `manifests/ingress.ts` | `buildIngress()`, `IngressTls` | Builds the app Ingress (Traefik class, one host rule to Service port 80, owner reference to the Deployment). With `tls` (set from `PIER_TLS_ISSUER`) it adds the cert-manager issuer annotation, the `<namespace>-pier-https-redirect@kubernetescrd` middleware and a `tls` entry with Secret `<name>-tls`. |
| `manifests/constants.ts` | `CPU_REQUEST`, `CPU_LIMIT`, `MEMORY_REQUEST`, `MEMORY_LIMIT`, `EPHEMERAL_STORAGE_REQUEST`, `EPHEMERAL_STORAGE_LIMIT`, `PROGRESS_DEADLINE_SECONDS`, TLS annotation keys, `HTTPS_REDIRECT_MIDDLEWARE`, `tlsSecretName()` | Resource and scheduling constants extracted to keep manifests/index.ts under 250 lines. |
| `create-app.ts` | `createApp()`, `createAppSerialized()`, `CREATE_APP_MUTEX_TIMEOUT_MS`, `AppExistsError`, `HostInUseError`, `CreateTimeoutError` | Orchestrates creation: pre-checks (deployment must not exist, host must not be in use in namespace), creates Deployment → Service → Ingress in order, rolls back on failure. `createAppSerialized()` serializes calls via a module-level promise chain (`createMutex`) with a **30s timeout** per create (`CreateTimeoutError` → route maps to 503). Correct only with one backend replica; see [../routes/README.md](../routes/README.md#app-creation-race-condition-and-the-create-mutex). |
| `app-actions.ts` | `scaleApp()`, `restartApp()`, `deleteApp()`, `DeleteAppResult` | Lifecycle actions using `getLiveApp()` for existence checks. `restartApp()` JSON-Patches `kubectl.kubernetes.io/restartedAt` with `op: add`. `deleteApp()` removes Deployment (foreground) plus Service/Ingress when live, or labelled orphans when the Deployment is gone; returns which objects were deleted. |
## Volumes

`volumes/` treats a PersistentVolumeClaim as a Pier volume. Attachments are read from the Deployment pod spec, while labels are only a listing convenience. New mounts use `pier-local`, `ReadWriteOnce`, and Recreate strategy; removing the last mount restores RollingUpdate. The local-path provisioner creates node-local directories, so requested size reserves quota but does not hard-limit disk use.
